# Veil Arena v0.3.0（ソース版・公開前の案）

他のVeilの変更を繰り返し試験するため、固定K3sの1 VM環境と実Keeper接続を追加しました。
Mac ARM64／QEMU TCGとLinux x86_64／KVMで、通信・指定checkpointの中断／期限検出・正常復帰を確認し、1 VM標準の機能開発を一区切りにします。
このノートは候補です。v0.3.0のタグ作成・公開はまだ行っていません。

## v0.2.1からの変更

- K3s・kernel・依存・air-gap OCI入力を固定して準備し、試験中にdownload/buildしない1ノードVM入口を追加。Pod Ready、Service DNS、TCP／UDPのnonce・受信件数を照合します。
- 固定KeeperのAppArmor exec smokeを接続。正常、拒否不成立の対照、限定exec拒否、profile解除後の正常復帰を判定します。対象VeilとArenaの責務を分けます。
- Node Ready後・Keeper開始前のcheckpointでrunnerの実停止を確認し、中断→正常→watchdog期限検出→正常の4 runを実行する入口を追加。部分証拠・証拠同期・所有QEMU回収を独立に検証します。
- netns一括試験を18ケースへ拡張。固定IPv4 TCPの初期SYN限定drop、対照通過、detach後復帰を比較します。BPF_PROG_TEST_RUNは109入力（従来70＋TCP 39）を照合します。
- SSD正式入口にwatchdog-dailyを接続し、本人実行の成功と証拠フォルダの表示を記録しました。
- F1起動PythonがNix closureへ含まれない問題と、Namespace作成直後にdefault ServiceAccountが未成立のままPodを適用する競合を修正。既存Pod期限内で依存成立を確認し、APIエラーを待機成功に変換しません。
- 2 VMの別ノード通信・Flannel/VXLAN・限定NetworkPolicyと解除の実装を保持しつつ、標準完成は1 VM、2 VMは追加検証へ整理しました。
- [他のVeilへの引継ぎプロンプト](../VEIL_HANDOFF.md)を追加しました。

## 確認した範囲

- F1最終修正ソースで、Linux x86_64／KVMとMac ARM64／TCGそれぞれ新規1 VMを順次2回実行し、通信・証拠同期・正常回収・異なるboot IDでの再成功を確認。
- 固定Keeper、checkpoint中断／watchdog後の復帰、Linux本人の4 run成功は、それぞれの専用記録で確認。
- PR #30と#31のマージ後main CIは成功。v0.3.0への版上げ後のチェックとPR CIは[公開準備記録](../V0_3_0_READINESS.md)へ分けて記録します。

これらは指定ソース・固定入力での過去の実VM証拠です。今回の版上げでv0.3.0 guestを新規ビルド・実起動したという主張ではありません。
CIの静的・単体・Nix定義評価もVM実起動とは別です。古いimmutableなrunner／guestは版や内容が自動更新されません。再利用時はホストUID・CPU系統・入力hash・実際の対象ソースを照合してください。

## 配布・制約・残るTODO

- ソースのみを配布します。VMイメージ・依存バイナリ・生disk・ログ・PCAP・kubeconfig・tokenは同梱しません。Rust・スクリプト・文書はMIT、参照eBPF CコードはGPL-2.0-onlyです。
- 標準K3s VMは4 vCPU・16 GiB RAM・32 GiB仮想disk。ホスト余力・disk条件は入口に従います。これは承認済み資源契約であり、最低必要量の測定値ではありません。期限・期待値は維持しています。
- Linuxの新規2 VM統合受け入れはCPU資源不足、Macの統合新規受け入れは事前確認時のRAM不足。2 VM checkpointも未完了です。過去のMac F2成功を現行両ホストの統合成功へ読み替えません。実装・証拠・TODOを保持します。
- 過去のLinux x86_64／KVM netns期限超過の根本原因は未確定。K3sの成功や診断改善で解消したとは扱いません。
- KeeperのPod配備、station-api・SQLite・独自BPF LSM・全機能や本番保護の認定は含みません。参照eBPFの成功も他のVeilの防御成功を保証しません。
- 物理環境は別プロジェクト。第三者試用、kind/kubeadm別実装、複数CNI、IPv6クラスタ、HA、任意時点の中断、kernel panic・電源断、Mac HVF、Linux ARM64/KVMは標準完成の範囲外です。性能・未知の攻撃への防御は保証しません。

以後は他のVeilの実開発を優先し、具体的な試験要求や不具合に応じてArenaを保守します。署名タグ・公開は別途承認後に行います。
