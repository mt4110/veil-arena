# Veil Arena v0.2.0

Veil開発での反復試験と失敗診断、NetEmによる損失の切り分け、
Macと外部SSDを使う専用Linux VMの正式入口を整えたソース版です。

## v0.1.0からの変更

- Blackholeオフライン試験の準備・反復・集計をまとめた `blackhole-workflow.sh`。
  失敗段階、実際と期待の違い、該当ログをコンソールへ表示します。
- 既存依存キャッシュを使う新しいチェックアウトで、正常・意図した失敗・正常への復帰を
  Mac／Linuxで確認した手順。cold installや第三者による再現の証明とは分けています。
- VM内のNetEm全損失と参照eBPFのdropを、送受信・kernel counter・qdisc counterで区別。
  設定不成立の検出と解除後の正常復帰を加え、一括試験は13から16ケースになりました。
- 外部SSDのマウント、固定guest入力、保存範囲、既存出力を検査する `arena-netns-volume`。
  読み取り専用のguest bundleと依存キャッシュを再利用します。
- 起動完了の単体試験fixtureを、内容の完成後に公開する方式へ修正。
  待機期限や期待値を緩めず、旧方式の競合と修正後の公開を回帰試験で確認しました。

## 確認範囲

本人によるBlackholeオフライン試験の実行・失敗診断・正常再実行を確認しました。
これは実BlackholeによるLive通信遮断の確認ではありません。

NetEmとSSD正式入口はMac ARM64／native QEMU・TCGで新規2 VM・各16ケースを確認済みです。
Linux ARM64／TCGのNetEm先行試験、Mac／Linux ARM64の静的・単体検査、
GitHub Linux x86_64の静的・単体検査とNix評価は、それぞれ別の証拠です。
PR #11マージ後main `87af46c` でも、SSD正式入口の既存イメージ・キャッシュを再利用し、
新規VM 1回・16ケースの期待結果一致、停止前の証拠同期、所有QEMUの正常回収を確認しました。
これは最終的な版上げ後コミットの受け入れではなく、公開準備時点のmainの結果です。

版上げ後も、0.2.0のホストcontroller・正式入口と検証済みguest bundleの組合せで、
追加の新規VMを含む2 VM・各16ケースの受け入れを確認しました。
両VMの異なるboot ID・同じ起動入力・停止前の証拠同期・所有QEMU回収を照合しています。
再利用guest内のArenaパッケージは0.1.0のままであり、0.2.0のソースから新たにビルドした
guestの実起動確認とは区別します。

Rust 1.98.1、Cargo実行バイナリ1.98.0、Python 3.14.7を固定しています。

[NetEmの検証記録](https://github.com/mt4110/veil-arena/blob/v0.2.0/docs/NETEM_COMPARISON_VALIDATION.md)、
[SSD正式入口の検証記録](https://github.com/mt4110/veil-arena/blob/v0.2.0/docs/VOLUME_ENTRY_VALIDATION.md)、

## 配布と制約

ソースのみを配布し、VMイメージ・依存バイナリ・ローカルの生ログ／PCAPは同梱しません。
Rust・スクリプト・文書はMIT、参照eBPFのCコードはGPL-2.0-onlyです。

現在の16ケースについてLinux x86_64／KVMで残る期限超過は未解決です。
以前の13ケースの成功を、現在の一括試験の成功とは扱いません。
IPv6のwire試験、TCPの限定drop、固定fixture以外の異常入力、任意時点の中断、
kernel panic・電源断、Mac／HVF、Linux ARM64／KVM、SSDの稼働中抜去・同時書換えは保証しません。
第三者試用・k8sは保留です。性能・作業時間の削減・製品価値は未測定です。
未知の攻撃への防御や、ホストの無条件な安全性を保証するものではありません。
